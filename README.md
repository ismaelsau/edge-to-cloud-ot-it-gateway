# Edge-to-Cloud OT/IT Integration Gateway
Arquitectura de monitoreo ambiental y supervisión de alarmas críticas mediante ESP32, MQTT, Node-RED y persistencia relacional en Supabase (PostgreSQL)

# Resumen Ejecutivo del Proyecto

Este proyecto implementa una arquitectura completa de **integración OT/IT (Nivel Campo a Nivel Nube)** orientada a la digitalización no invasiva (retrofitting) de áreas industriales o cabinas de proceso. 

El sistema adquiere variables ambientales analógicas y supervisa canales digitales de seguridad mediante aislamiento galvánico en el borde (Edge), desacopla la carga del microcontrolador mediante mensajería asíncrona MQTT, orquesta la supervisión operativa local a través de un SCADA ligero en Node-RED y persiste la telemetría en tiempo real dentro de una base de datos relacional PostgreSQL en Supabase vía API RESTful.

# Capa,Componente / Tecnología,Rol / Justificación Técnica
1. OT / Campo - Sensor DHT22 & Optoacoplador PC817 - Adquisición ambiental y aislamiento galvánico de señales críticas de paro contra transitorios y bucles de masa.
2. Edge Device - ESP32 (MicroPython) - "Procesamiento local en el borde, formateo de payloads JSON y publicación ligera sin sobrecarga HTTP."
3. Transporte - MQTT (HiveMQ) - "Protocolo Publish/Subscribe de baja latencia y mínimo ancho de banda, desacoplando el hardware de la red corporativa."
4. Middleware - Node-RED (Node.js) - Gateway multipropósito: actúa como SCADA local resiliente (continúa operando sin internet) y adaptador de protocolos.
5. Cloud IT - Supabase (PostgreSQL) - Persistencia estructurada de series temporales mediante motor relacional con interfaz PostgREST.

# Decisiones Clave de IngenieríaAislamiento Galvánico en Hardware:
1. Se integró un optoacoplador PC817 en el canal digital del ESP32 (GPIO 16) para recibir contactos secos o señales industriales (24V simuladas) mediante acoplamiento óptico, protegiendo las líneas lógicas de 3.3V del microcontrolador ante sobretensiones de planta.
2. Desacoplamiento Edge-to-Cloud vía MQTT: En lugar de realizar peticiones HTTP pesadas directamente desde el ESP32 (lo que satura la memoria RAM y bloquea el chip negociando certificados TLS), el microcontrolador despacha paquetes JSON ultraligeros hacia el broker MQTT, delegando la carga computacional de red al Gateway local.
3. Operación Local Continua (Resiliencia OT):Si la conexión a la nube o el enlace a internet se interrumpe, el Dashboard SCADA en Node-RED (:1880/ui) continúa funcionando al 100% de forma local, garantizando la supervisión operativa del personal de planta.
4. Optimización de Ingesta Cloud (Deadband / Filtrado por Excepción): Modo Demostración: Muestreo continuo a alta frecuencia (2s) para validación visual de reactividad instantánea.Escalabilidad en Producción 24/7: La arquitectura contempla la integración de lógica Report by Exception (Deadband) en Node-RED para registrar en base de datos únicamente variaciones térmicas significativas o eventos discretos de alarma (CRITICAL), reduciendo la escritura en PostgreSQL en más del 85%.
